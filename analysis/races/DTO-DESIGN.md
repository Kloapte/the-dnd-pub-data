# Race and Species DTO Design and Implementation

The public API uses a unified `RaceDto` for race/species and subrace records, with `RaceDefinitionKind` identifying `RACE` or `SUBRACE`. Each definition has a source-aware ID and primary `SourceReference`. Subraces include a `RaceParentReferenceDto` with the parent's ID, name, and source. PHB and XPHB records remain independent; same-name/source subraces under different parents retain their parent-qualified IDs.

`RaceSummaryDto` carries ID, name, primary source and page, definition kind, optional parent, structured size, scalar walking speed, and source-derived lineage metadata. It contains no selectable flag because the source does not define one. Nameless auxiliary records are import-only, not summary entries.

`RaceDto` carries explicit edition and creature type metadata, size, movement components, fixed and choice ability increases, typed grouped proficiency grants, language grants, senses, damage/condition protections, additional spell grants, trait names and tags, aliases, lineage, age and height/weight values, overwrite fields, additional/other source references, and reprint references. Movement values preserve either numeric feet or the source's boolean marker. Spell schedules reuse the existing Feat spell grant DTO hierarchy because its structured semantics are equivalent. Choice counts, candidate lists, category filters, level keys, and usage keys are preserved.

The mapper consumes Stage A `RaceDefinition` values. It reads typed source references from the attached source record where Stage A preserves them, and uses normalized mechanics for structured grants. It does not combine parent and subrace mechanics. Internal entries, source availability flags, sound/media paths, copy/version metadata, template variables, and import provenance are excluded. All public records use `@JsonInclude(NON_EMPTY)`, immutable lists, and preserve meaningful false/zero values.

The immutable `RaceCatalog` owns startup loading and indexes by ID, normalized name, source, and definition kind. `RacesService` owns query filtering and detail mapping; `RacesController` provides `GET /api/races`, `GET /api/races/{id}`, and `GET /api/races/by-name/{name}?source=`. Name lookup returns all source-specific and parent-specific matches. The fixed catalog contains 356 records, so collection pagination is currently unnecessary.

The corpus contains 160 race roots, 98 subrace records (five nameless auxiliary), and 103 expanded versions. The catalog contains 356 definitions. No character selection, character-state mutation, parent/subrace combination, or mechanical effect execution is performed.
