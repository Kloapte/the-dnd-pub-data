# Feat DTO implementation

The catalog loads 305 root records from the packaged `data/feats.json` resource, expands 9 declared versions, and indexes 314 normalized definitions. It tracks root and variant counts separately. IDs follow `feat:<source-slug>:<name-slug>`, preserving source spelling and page. Primary, additional, reprint, and variant source codes are validated against the shared Source Registry. Duplicate IDs and case-insensitive `(name, source)` pairs are rejected.

`FeatVersionExpander` inherits parent fields and applies only the observed `_mod.entries` instructions in order: `replaceArr` by name or index, and `removeArr` by names. Unsupported modes, selectors, targets, or payloads fail explicitly. Variants preserve declared name/source and override `additionalSpells` when supplied. Root definitions remain unchanged. Normalized definitions mark variants and retain their parent IDs; `FeatExpansionProvenance` stores declaration/index separately in internal import records.

Typed DTEs cover root properties, prerequisite groups, ability increases, proficiency grants, senses, resistances, spell grant trees, optional-feature progression, and version instructions. The normalized model carries typed spell grants. Public spell grant DTOs represent ability names/choices and recursive typed values (text/query, array, keyed object, count, flag). The corpus spell-grant values have no inline markup. Public projections omit raw entries, `_mod`, source availability metadata, and expansion provenance.

`FeatDto` exposes stable ID, name, `SourceReference` including page, category, safe prerequisite groups, ability increases, reprint references, repeatability, and structured additional spell grants. `FeatSummaryDto` remains concise. `NON_EMPTY` serialization omits null/empty values and retains meaningful zero and false values. Prerequisite display prose, markup, publication metadata, and import diagnostics are not exposed.

Endpoints: `GET /api/feats` (optional `name`, `source`, `category`), `GET /api/feats/{id}`, and `GET /api/feats/by-name/{name}?source=`. Name lookup returns all source-specific matches when source is omitted; generated variants use the same routes. For semicolon names, the controller reads and decodes the original request URI so the variant suffix is not lost as a matrix parameter.

Validation: full `mvn test -q` completed successfully with **111 tests, 0 failures, and 0 errors** (baseline 107). Tests cover 305 roots, 9 variants, 314 catalog definitions, variant IDs and names, inheritance, operation order and rejection, spell grant projection, REST retrieval, packaged resources, and existing pipelines.
