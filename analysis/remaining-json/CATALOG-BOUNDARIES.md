# Proposed Catalog Boundaries

IDs below are design candidates, not final contracts. Preserve source codes exactly and include parent/category context when source evidence requires it. Use catalog-owned indexes rather than recomputing IDs from arbitrary names. Do not Base64-encode IDs or collapse editions/reprints.

| Proposed catalog | Source collections | Boundary and candidate identity | Parent/source concerns | Public API shape proposal |
|---|---|---|---|---|
| Adventure Index | `adventures.json:adventure` | Publication metadata records; candidate `adventure:<source>` with source code as authored identity | Records are navigation indexes, not chapter content. Verify `source` uniqueness and preserve group/storyline. | Summary/detail read routes only if users need adventure navigation; no chapter-text endpoints. |
| Bastion Facilities | `bastions.json:facility` | Facility definition, candidate `facility:<source>:<name>` | This file is a facilities subset, not full Bastion/turn/economy rules. Preserve level, type, prerequisites, space. | `GET /api/bastion-facilities`; detail by stable ID. |
| Character Creation Options | `charcreationoptions.json:charoption` | Option catalog, candidate `char-option:<source>:<optionType>:<name>` | Inspect source keys and option types for collisions; preserve choices/prerequisites as authored. | Collection/detail endpoints, filters by option category/source. |
| Cults | `cultsboons.json:cult` | Cult definition, candidate `cult:<source>:<name>` | Keep distinct from the separate boon collection; source prose and creature-like entries. | Cult summary/detail. |
| Boons | `cultsboons.json:boon` | Boon definition, candidate `boon:<source>:<name>` | Preserve prerequisite and grant structures without character application. | Boon summary/detail. |
| Deities | `deities.json:deity` | Deity references, candidate `deity:<source>:<pantheon>:<name>` | Five PHB `(name,source)` duplicate groups demonstrate pantheon context is required. Reprints and `_copy` also need explicit handling. | Summary/detail can expose identity, pantheon, domains and safe metadata; prose requires publication review. |
| Encounters | `encounters.json:encounter` | Encounter table/definition, candidate `encounter:<source>:<name>` | Distinguish encounter record from a generated encounter and from adventure contents. Resolve explicit monster/item refs only. | Encounter table summary/detail, no generator unless separately specified. |
| Crochet Patterns | `homecrafts.json:crochetPattern` | Craft pattern, candidate `crochet-pattern:<source>:<name>` | This is a hobby instruction domain; content usefulness and publication rights need review before API inclusion. | Defer public API pending product/licensing decision. |
| Treasure Tables | `loot.json` collections `individual`, `hoard`, `magicItems`, `dragon`, `dragonMundaneItems`, `gems`, `artObjects` | One domain module may own distinct typed table types; candidate IDs need collection kind, source, and table name | Dynamic currencies, dice rolls and table outputs are not concrete Item definitions. `linkedLootTables` is auxiliary in `magicvariants.json`. | Typed table read API if needed; do not materialize random outcomes or generate Items. |
| Name Tables | `names.json:name` | Name-generation table, candidate `name-table:<source>:<name>` | Tables are data for selection/generation, not individually addressable character names. | Consider a table API with controlled query semantics; no generated-name endpoint without a product decision. |
| Objects | `objects.json:object` | `ObjectDefinition`, ID `object:<source>:<normalized-name-slug>` | 37 source/name identities are unique; distinct from statted creatures and equipment items. | Implemented summary/detail API; see `objects/IMPLEMENTATION.md`. |
| Recipes | `recipes.json:recipe` | `RecipeDefinition`, ID `recipe:<source>:<normalized-name-slug>` | Food and cocktail content, not crafting rules; ingredients are not Item references. | Implemented metadata-only `/api/recipes`; full content remains internal pending publication review. |
| Homecraft | `homecrafts.json:crochetPattern` | Excluded hobby-pattern domain (20 source records) | Explicit product decision: OUT OF SCOPE. | No catalog or API. |
| Rewards | `rewards.json:reward` | Reward definition, candidate `reward:<source>:<name>` | Preserve categories, prerequisites and grants; do not apply to characters. | Summary/detail with source/category filters. |
| Traps | `trapshazards.json:trap` | Trap definition, candidate `trap:<source>:<name>` | Keep distinct from hazards even though co-located. Structured ratings and countermeasures need typed forms. | Summary/detail. |
| Hazards | `trapshazards.json:hazard` | Hazard definition, candidate `hazard:<source>:<name>` | Separate identity/category from traps; avoid generic effect execution. | Summary/detail. |
| Variant Rules | `variantrules.json:variantrule` | Rule reference definition, candidate `variant-rule:<source>:<name>` | Preserve ruleType and authored source; descriptive text is not a generic executable rules engine. | Summary/detail with source/type filters; public prose subject to rights review. |
| Vehicles | `vehicles.json:vehicle` | Vehicle stat definition, candidate `vehicle:<source>:<name>` | Multi-source names and editions; preserve reprints, statistics and entries. Do not merge with Objects/Items. | Summary/detail, source/type filters. |
| Vehicle Upgrades | `vehicles.json:vehicleUpgrade` | Upgrade definition, candidate `vehicle-upgrade:<source>:<name>` | Preserve compatible vehicle filters and adjustment data; do not apply or calculate vehicle stats. | Independent detail or nested resource under vehicle only if source establishes parent linkage. |

## Shared support versus separate public catalogs

`books.json` and `sources/registry.json` are already implemented support catalogs. `_meta`, index manifests, type/entry templates, and linked-table structures should normally remain import support unless clients need them independently. Separate root collections may share a loader but should not be forced into one public DTO if their semantics diverge. In particular, Cults/Boons, Traps/Hazards, Vehicles/Upgrades, and the seven loot table families need distinct typed variants or separate definition records.

No separate fluff files occur in this snapshot. Embedded descriptive entries stay internal unless a publication review authorizes a specific field. Index metadata such as adventure contents can support navigation without exposing source chapter prose.
