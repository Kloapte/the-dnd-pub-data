## Pinned source

snapshot. Its SHA-256 is

## Purpose and domain evidence

The records are real-world cooking and cocktail recipes published as D&D-themed culinary content,
not game crafting recipes or consumable-item rules. `ingredients` and `instructions` occur in all
316 records. The source contains 2,802 root ingredient-array entries, including grouped ingredient
sections; those groups contain a further 698 entries. There are 80 equipment entries, 1,135
instruction-array entries (including 91 grouped instruction sections), and 275 cook-note entries.
The instructions describe ordinary food preparation, cooking, chilling, and serving.

No authored skill checks, ability checks, DCs, costs, currency, preparation/cooking-time fields,
durations, rarity, prerequisites, outputs, effects, yields, or crafting mechanics occur. `serves`
records serving counts (exact or min/max) and `makes` is a separate string on 93 records and a
number on one; neither is treated as a game mechanic. The source contains no `_copy`, `_versions`,
`reprintedAs`, root `entries`, output-item links, or media paths. Source-authored recipe names,
ingredients, instructions, cook notes, and some alternate names are expressive cookbook content.

## Source validation findings

Primary sources are HF 79, HFFotM 76, HFLotT 75, PaF 76, and HFDoMM 10. Secondary citations are
HFDoMM (40), HFLotT (five citations with pages), and HFStCM (one citation without a page). Before
this implementation, HFDoMM was the only primary source code absent from the Source Registry. It occurs on
10 root records, in their source lineage, and in the HFLotT Book Catalog's authored contents
headers. Its exact publication title and standalone Book Catalog record are absent. The
implementation registers the code with no alias or invented publication metadata, retaining the
source identity while marking publication metadata unavailable.

## Embedded markup and explicit relationships

The corpus contains 96 `{@unit ...}` formatting tags, eight `{@recipe ...}` links, one
`{@creature ...}` token, and one external `{@link ...}`. The recipe links reference recipe names,
but Recipe is not an existing supported resolver target kind; the creature target is also
unsupported. These exact tokens remain in typed internal source content. They produce zero new
shared resolver occurrences and no inferred target IDs. Ingredient strings are never converted
into Item references. See [`REFERENCE-INVENTORY.md`](REFERENCE-INVENTORY.md).

## Audit limitations

The resource snapshot itself has no release marker; v2.37.0 is the repository's pinned dataset
context. The code `HFDoMM` is preserved exactly, but no publication title is guessed. Source text
is fully retained internally by the implementation and withheld from public projections.
