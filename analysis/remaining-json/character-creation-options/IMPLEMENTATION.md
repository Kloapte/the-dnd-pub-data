# Character Creation Options implementation

## Discovery and identity

The pinned `data/charcreationoptions.json` resource contains 44 `charoption` roots, 62 recursive field paths, six primary source codes, and four authored option type codes. The complete path/type/occurrence inventory is in [FIELD-COVERAGE.md](FIELD-COVERAGE.md), generated by [discover-char-options.mjs](discover-char-options.mjs); the machine-readable result is [discovery-evidence.json](discovery-evidence.json).

Every root has one source, name, positive page, one-element `optionType` array, and `entries` array. `(source, optionType, name)` has no collisions. IDs use `char-option:<source-slug>:<type-slug>:<name-slug>`, for example `char-option:idrotf:cs:alagondar-scion`. The source spelling is retained in `SourceIdentity`. `RF:B` is preserved as authored in the category value and represented as `rf-b` only in the ID component. The source codes are `EGW` (1), `HotDQ` (2), `IDRotF` (17), `MOT` (9), `OotA` (2), and `VRGR` (13). Option types are `CS` (17), `DG` (8), `RF:B` (9), and `SG` (10).

## Typed source and normalized model

- `CharacterCreationOptionDte` and `CharacterCreationOptionsFileDte` map roots strictly. Prerequisites, race names, secondary source references, and reprint UIDs use dedicated DTEs.
- The source's mixed text/object `entries` reuse the existing strict `EntryDte` model because the observed `entries`, `list`, and `table` forms have the same semantics as existing catalog entry content. Corpus loading covers 64 direct strings and 38 direct objects plus nested entry/table shapes.
- `CharacterOptionMapper` creates immutable `CharacterOptionDefinition` values and `CharacterOptionImportRecord` provenance. Descriptive entries and the source-only `hasFluffImages` flag remain internal provenance. No copy/version declarations occur; no expansion is performed.
- Source pages, two `otherSources` references, and both `reprintedAs` targets are retained. Reprint UIDs are parsed as `Name|Source` and validated, but no target definition is inferred.

## References and source validation

All six primary sources, the secondary source `ToD`, both reprint target sources `RHW`, and source codes in the observed `book`/`deck` inline tags are registered. No registry addition was required.

The structured reference inventory has six unqualified race names inside two prerequisite groups and two explicit `reprintedAs` UIDs tagged `background`. `RACE` and `BACKGROUND` are not supported target kinds in the shared resolver. These eight occurrences remain typed and receive no inferred target IDs. Two `otherSources` values are publication provenance, not definition references. Markup mentions are descriptive content and are not extracted as grants. The existing resolver snapshot remains at 3,875 occurrences with its established outcome counts; no new resolver occurrence was added.

See [REFERENCE-INVENTORY.md](REFERENCE-INVENTORY.md) for occurrence-level classifications and boundaries.

## Public API

The catalog exposes:

- `GET /api/character-creation-options` with optional `name`, `source`, and `optionType` filters. Name filtering is case-insensitive substring matching; source/category comparisons are case-insensitive.
- `GET /api/character-creation-options/{id}` for detail.
- `GET /api/character-creation-options/by-name/{name}?source=` for exact case-insensitive name lookup, retaining all matches unless the source filter narrows them.

There are 44 fixed records, so the list endpoint is unpaginated. Summary fields are ID, name, source/page, and authored option type codes. Detail adds structured race prerequisite names, authored reprint target name/source/kind, and secondary sources. Prerequisite notes and all descriptive entries/tables, inline markup, and `hasFluffImages` are excluded. No grant mechanics are inferred from the entries, and no character eligibility/application endpoint is present.

## Validation

Dedicated tests cover all 44 roots, type/source distribution, IDs and collision rejection, source registry validation, strict unknown-field and entry-shape rejection, nested entry preservation, prerequisites, reprints, source-aware filtering, public serialization exclusions, endpoints, packaged-JAR resource loading, and unchanged 3,875-reference resolver outcomes.

Full `mvn -q test`: **303 tests, 0 failures, 0 errors**. This count includes the 292-test baseline plus 11 focused Character Creation Option tests.
