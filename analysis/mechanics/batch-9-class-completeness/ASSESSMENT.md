# Batch 9 — Class Ability and Choice Completeness Assessment

## Scope and method

This audit covers the pinned Class source files under `src/main/resources/data/classes/` and the current Class and Subclass normalization and public projection paths. It traces the authored `abilityDc`, `abilityAttackMod`, and `type=options` nodes through the typed entry deserializer, effective Class copy resolution, normalized feature graph, and public feature mapper. No production source, API contract, tests, or source data were changed.

The reproducible source traversal is [`audit-source.mjs`](audit-source.mjs). Its machine-readable output, including every source pointer, owner context, all option reference tokens, entry labels, source qualification, and resolution result, is [`source-occurrences.json`](source-occurrences.json). Run it from the repository root with `node analysis/mechanics/batch-9-class-completeness/audit-source.mjs`.

## Findings

| Scope | Authored occurrences | Effective occurrences | Internal result | Public result |

| `abilityDc` | 16 | 16 | COMPLETE | INTENTIONALLY_WITHHELD |
| `abilityAttackMod` | 13 | 13 | COMPLETE | INTENTIONALLY_WITHHELD |
| Typed `options` nodes | 40 | 40 | COMPLETE | 36 complete as reference lists; 2 partial metadata; 2 withheld and omitted |

The source audit scans 15 Class JSON documents and 2,176 authored Class Feature and Subclass Feature roots. The normalizer's copy resolver preserves authored `entries` as an atomic field: a present value overrides the base and an absent value inherits it. None of the 29 ability declarations or 40 option nodes are inherited by a copy-effective record. The effective counts therefore equal the authored counts. The evidence script independently follows the current copy identity fields and checks this result. No feature identity or selection is generated by this audit.

### Ability declarations

`ClassEntryDeserializer` maps both tags to [`ClassAbilityEntryDte`](../../../src/main/java/com/thedndpub/data/dte/classes/ClassAbilityEntryDte.java), retaining `type`, `name`, and the ordered `attributes` list. [`ClassFeatureContentNormalizer`](../../../src/main/java/com/thedndpub/data/importer/classes/ClassFeatureContentNormalizer.java) maps each directly to [`ClassFeatureAbilityDeclaration`](../../../src/main/java/com/thedndpub/data/dto/classes/ClassFeatureAbilityDeclaration.java), whose immutable `abilities` list retains the authored values. The enclosing `ClassFeatureDefinition` or `SubclassFeatureDefinition` retains feature identity, source, parent class/subclass, level, and source provenance.

No ability identifier or ordering loss was found. The 29 declarations have 30 attribute elements because one declaration carries two alternatives (`str`, `dex`). Observed attribute tokens are `cha`, `int`, `spellcasting`, `str`, and `wis`; no normalization into ability IDs, derived modifier, DC, or attack bonus occurs.

The public `ClassFeatureDto` and `SubclassFeatureDto` use `ClassFeatureMechanicsDto`, which collects reference IDs, reference-backed choices, and consumption. It does not project `ClassFeatureAbilityDeclaration`. The class/subclass detail endpoints expose feature unlock references; feature detail endpoints do not publish feature `content`. This is a deliberate withholding boundary for the authored feature entry body, not a normalization defect. Classification for all 29 rows below: internal COMPLETE; public INTENTIONALLY_WITHHELD.

### Option structures

`ClassEntryDeserializer` maps `type=options` into [`ClassOptionsEntryDte`](../../../src/main/java/com/thedndpub/data/dte/classes/ClassOptionsEntryDte.java), retaining nullable `count`, nullable `style`, and the ordered recursive `entries` list. The normalizer creates [`ClassFeatureChoice`](../../../src/main/java/com/thedndpub/data/dto/classes/ClassFeatureChoice.java) and maps every child through the same recursive feature-content normalizer. Child text remains `ClassFeatureText`; named sections/list wrappers remain `ClassFeatureSection`; same-domain feature references become exact `ClassFeatureReferenceNode`; external option references become `ClassExternalFeatureNode`. All collections are defensively immutable.

The source has 40 option nodes: 12 in Class Feature roots and 28 in Subclass Feature roots. There are no nested `type=options` nodes within these 40. Twenty-five carry a numeric `count` (17 with `1`, six with `2`, two with `3`); 15 omit it. Three carry `style=list-hang-notitle`; 37 omit style. The normalizer and public mapper preserve present count/style values and do not fill in omitted values.

Every one of the 40 nodes is internally COMPLETE. The 222 reference alternatives are retained in source order. Their source and resolution inventory is:

| Authored reference kind | Count | Resolution result | Qualification caveat |
|---|---:|---|---|
| `refClassFeature` | 8 | 8 exact internal feature targets resolve | Blank UID source components use the resolver's PHB fallback |
| `refSubclassFeature` | 53 | 53 exact internal feature targets resolve | Blank UID source components use the resolver's PHB fallback |
| `refOptionalfeature` | 161 | 161 exact target matches | 101 carry a source in the authored UID; 60 are unqualified and the existing class resolver defaults them to PHB |
| `refFeat` | 0 | — | None observed |
| Ambiguous, unresolved, or unsupported targets | 0 | — | No such outcomes among these 222 nodes |

The 60 unqualified Optional Feature references all match one PHB source record under the current resolver rule. Two occur under the XGE `Fighting Style` feature (`Dueling` and `Two-Weapon Fighting`); the other 58 are under PHB-authored feature owners. The source token itself remains unqualified in the evidence file. This audit reports the application's existing default and does not independently establish the author's intended source for an unqualified token.

The public mapper turns reference-only choices into `ClassFeatureChoiceDto(count, style, options, groups)`. For 36 nodes, all child nodes are references and the projected alternatives, authored count (when present), and style (when present) are represented as lightweight references. These are COMPLETE at that reference-list projection level; feature descriptions and mechanics remain in their own catalogs and are not copied into the choice response.

Two reference-only nodes contain additional authored choice metadata that the public projection omits:

| Feature | Source location | Omitted source information | Public consequence |
|---|---|---|---|
| Rune Carver (Fighter, Rune Knight, level 3) | `class-fighter.json#/subclassFeature/55/entries/5` | Two reference `name` overrides carry authored level qualifiers | Alternatives are listed by referenced identity/name, without the two authored labels |
| Elemental Disciplines (Monk, Four Elements, level 3) | `class-monk.json#/subclassFeature/8/entries/1` | Nine reference `name` overrides carry authored level qualifiers; one reference has `data.isRequiredOption=true` | The public list omits all nine display qualifiers and the required-option marker |

The normalized `ClassExternalFeatureNode` retains these values (`name` and `required`), but `ClassPublicMapper.mapChoiceNodes` constructs `ClassChoiceReferenceDto` from the resolved reference and does not forward them. These two occurrences are internally COMPLETE and publicly PARTIAL_PUBLIC.

Two option nodes are text/section-only and have no `count` or `style`:

| Feature | Source location | Internal alternatives | Public consequence |
|---|---|---|---|
| The Third Eye (Wizard, Divination, level 10) | `class-wizard.json#/subclassFeature/27/entries/1` | Four named sections | The choice node and its alternatives are omitted |
| Master Transmuter (Wizard, Transmutation, level 14) | `class-wizard.json#/subclassFeature/58/entries/1` | Four named sections | The choice node and its alternatives are omitted |

The section names and nested entry bodies are retained in the internal `ClassFeatureSection`/`ClassFeatureText` tree. The public mapper intentionally withholds that prose-bearing feature content. It filters these `ClassFeatureChoice` nodes because they have no count/style and their children map to no public references/groups. This is INTENTIONALLY_WITHHELD for content, but PARTIAL_PUBLIC for structural completeness: a consumer can receive no `mechanics.choices` field and cannot distinguish “there is no choice” from “a choice exists but its alternatives were withheld.” No alternative count is recommended without publication and contract review.

## Concrete projection examples

For a reference-only choice such as PHB Totem Spirit, the internal choice retains count `1` and five ordered `ClassFeatureReferenceNode` alternatives. The public choice projection retains that count and the five lightweight feature references. It does not expose the referenced feature bodies.

For the XGE Rune Carver choice, the internal optional-feature reference nodes retain the authored display labels that state level qualifiers. The public `ClassChoiceReferenceDto` instead uses `ClassExternalReference.name`, which is the reference target name, and therefore omits the source `ClassReferenceEntryDte.name` override. The target ID still resolves. This is a metadata completeness loss, not an unresolved-reference defect.

For The Third Eye and Master Transmuter, the internal choice has four named section children in each case. Because all children normalize to descriptive section/text nodes and the source supplies neither count nor style, `mapChoice` produces an empty options/groups DTO; `collect` drops it. The public response therefore does not indicate that a source option group exists.

## Defects, intentional exclusions, and risk

1. **No internal preservation defect:** all 29 ability declarations and 40 option groups survive typed deserialization and normalization, including order and context. Copy resolution does not add inherited occurrences.
2. **Intentional publication limit:** ability declaration nodes and the two prose-bearing option sets are omitted with the feature entry body. This report does not recommend publishing descriptions, ability declarations, or option prose.
3. **Public completeness gaps:** two reference lists omit source-authored choice labels/qualifiers and one `isRequiredOption` flag. Two text-only source option groups are omitted without a structural signal. A consumer can mistake the latter omission for there being no choice, and can mistake the Rune Carver/Elemental Disciplines public candidate labels as unqualified.
4. **Compatibility:** adding `complete`, `withheld`, `availableAlternativeCount`, or `required` to public DTOs would change response JSON. No such change is authorized by this analysis. Prefer an additive, explicitly reviewed completeness indicator over changing `options` semantics or publishing full entry content.
5. **Qualification caveat:** 60 Optional Feature refs and blank source components on internal feature UIDs resolve through the existing PHB fallback. All match uniquely in the current source catalogs, but the source does not explicitly qualify those tokens. The audit does not change or expand resolver rules.

## Recommended minimal batches

Ranked recommendations for separate authorization:

1. **Correct the two reference-backed metadata losses** if publication review permits: preserve the 11 source display labels and the single authored required-option flag in an additive field or a carefully specified projection. Test exact source value and current reference IDs. Do not convert labels into character-level eligibility logic.
2. **Add an honest public completeness signal** for choice projections, distinguishing a complete exposed reference list from source options withheld under publication rules. For The Third Eye and Master Transmuter, the safer first choice is a boolean/status on the mechanics/choice projection, not inferred `count=4` or publication of prose. This is an API contract change and needs consumer and licensing review.
3. **Keep ability declarations internal** unless a separately approved field-level publication decision establishes a useful DTO shape and rights basis. There is no normalization work to do.
4. **Review PHB fallback provenance** separately for the 60 unqualified references, especially `Dueling` and `Two-Weapon Fighting` in the XGE Fighting Style group. Do not change resolution based only on this audit.

## Open questions

- Should public Class feature mechanics explicitly report that some source-authored alternatives are withheld, or should that information remain an internal importer diagnostic?
- Are the 11 level-bearing reference labels intended as presentation-only aliases, eligibility restrictions, or both? The label string itself is not an eligibility engine.
- What public meaning should `data.isRequiredOption=true` have, and should that field be eligible for exposure?
- Is the current implicit PHB source fallback acceptable for unqualified Optional Feature tokens under non-PHB owners?
- Should a future API represent the four named alternatives in The Third Eye and Master Transmuter by safe labels/count metadata, after licensing review, or only mark the choice as withheld?
