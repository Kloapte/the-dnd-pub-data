# Corpus Mechanics Inventory

Generated by `node analysis/mechanics/write-corpus-inventory.mjs` from parsed-source evidence and the manually reviewed dispositions in `catalog-review.mjs`.

Coverage: **36 catalog domains**, **43 definition-source collections**, **14,399 authored root records**. The existing catalog contracts account for **14,797 effective definitions** after expansion/auxiliary handling. This scanner does not execute copy/version resolution; effective counts come from the cited implementation contracts.

All 175 resource files are fingerprinted. Homecraft has 20 records and is excluded by product decision. The 812 supporting root units include registry records, metadata objects, templates, auxiliary records and shared table rows; they are not 812 additional catalog definitions. Five nameless Subrace roots are auxiliary. Source-family count (30), public catalog-domain count (36), and root-collection count (43) intentionally describe different boundaries.

Counts below use authored roots, not effective-copy occurrences. Tags include nested tags and transformation declarations; per-context counts are available in `corpus-evidence.json`. A keyword count is a review lead, never an extracted effect count. A typed table node is not automatically mechanical or eligible for publication.

## Support and non-effect data

Status (five records), LanguageScript (six), Item groups/types/properties/masteries/templates, Monster legendary groups/templates, class/bestiary `_meta`, linked loot tables, shared Dragon mundane rows, and Source Registry are scanned as supporting units. Status is typed/validated support, not a third Condition/Disease API. This corrects the historical coverage-matrix shorthand without opening a new catalog family.

Legendary group lair/regional entry content can contain mechanics and is included in support tag counts. It is not duplicated as a new Monster effect or integrated into the shared resolver. Raw `_copy`/`_mod`/`_versions` data is syntax evidence, not a second effective application of a mechanic.

## What changed since Step 3

The spell investigation remains the reference for the original 969-spell entry analysis. Its 642 damage, 126 dice, 148 scaledamage and 14 scaledice counts are reproduced. Its `structuredFieldSpellCounts.scalingLevelDice = 5` is an array-only counter defect: the complete field count is 41 (36 objects and five arrays). The production union already handles both; this is an evidence correction, not a newly discovered production scaling omission.

The old claim that area dimensions universally require prose is too broad. Seventy-eight spell roots explicitly encode non-point range geometry and numeric distance (emanation 26, cone 17, radius 16, line 10, sphere five, cube three, hemisphere one). Those range structures are already normalized/public. This does not supply an effect radius for a point-range spell such as PHB Fireball, whose separate radius remains in entries.

Earlier condition/scaling keyword counts are not extrapolated to other catalogs. This scanner finds 225 conditional-keyword Recipes, four save-keyword Adventure indexes and four healing-keyword Book indexes: concrete evidence that lexical matches are not effects. Different path conventions and inclusion of support/transform nodes also explain differences from earlier field inventories.
