# 7.3.2 — Shield mechanics extraction and REST integration

Status: implemented and verified, 18 October 2026. Scope is PHB and XPHB Shield only.

## Design checkpoint

The existing canonical payloads, evidence types, review/rights metadata and inspection DTOs remain
the contract. Startup extraction consumes normalized Spell definitions and verified authored source
fields. A dedicated evidence adapter checks resource SHA-256, authored ownership and agreement
with normalized values before constructing exact UTF-16 text evidence or structured-field hashes.
The two v2.37.0 source fingerprints are explicitly pinned; changing either requires source review.

Five bounded pattern IDs from 7.3.1 produce the reaction, AC modifier, declared duration,
turn-boundary duration and spell-specific prevention claims. The shared balanced parser reads
authored spell tags; plain XPHB trigger text never acquires the body's source qualifier or a target ID.
Production code has no dependency on benchmark fixtures or test authoring helpers.

Grammar misses produce evidence-backed unsupported constructs and retain independently supported
patterns. Integrity errors, I/O errors and invalid canonical joins fail startup. They are not converted
to successful empty inspection envelopes. Successful documents remain PARTIAL, with the main
entry still marked unassessed as a whole. Individual bounded claims can be complete without
establishing whole-Spell coverage. Existing canonical quality checks derive pending versus
mechanics-review-needed states; all rights remain NEEDS_REVIEW and P1D remains independent.

The inspection catalog will still contain 969 owners and all 930 formula references. Only the two
Shield owners become PROCESSED; the other 967 retain their existing unattempted documents.
Default responses, routes and DTO constructors remain unchanged.

## Implementation architecture

All six new production files are under
[`mechanics/spell`](../../../src/main/java/com/thedndpub/data/mechanics/spell/):

| Type | Responsibility |
| --- | --- |

| `ShieldMechanicsEdition` | Explicit PHB/XPHB input IDs, source fingerprints and attack-event dialect; not edition inference or a review decision |
| `SpellMechanicsEvidenceSource` | Original-byte/owner/normalized-value checks; source hierarchy, fingerprints, text spans, structured evidence and deduplication |
| `ShieldMechanicsExtractor` | Five bounded patterns consuming normalized values and verified source evidence; uses Batch 5 `BalancedMarkupParser` |
| `ShieldMechanicsAssembly` | Local builder, controlled abstentions and final immutable canonical document |
| `ShieldPatternMismatch` | Controlled pattern-failure reason and source pointer; integrity exceptions do not use this channel |

[`SpellMechanicsInspectionCatalog`](../../../src/main/java/com/thedndpub/data/services/SpellMechanicsInspectionCatalog.java)
now invokes extraction between the unattempted document factory and the existing complete
owner/index/source validation and DTO projection. Its explicit-document constructor remains usable
for canonical projection tests and future adapters. No controller, service query method, canonical
model, DTO, normalized definition or global Jackson setting changed.

The startup sequence reads two original resources for evidence after the existing typed manifest
has loaded the 18 Spell files. This is startup work, not request work. Requests retrieve the same
cached immutable inspection DTOs. The adapter does not execute rules, consult benchmark resources,
read approval manifests or require P1D authorization.

## Five patterns and source distinctions

| Pattern / stable slot | Source-supported output and bounds |
| --- | --- |
| `shield-reaction-v1` / `activation` | Exactly one reaction from structured time metadata; fully matched ordered attack-hit OR Magic-Missile-targeting condition. Notes, alternative action costs and unrecognized trigger wording abstain |
| `shield-ac-v1` / `ac-bonus` | Authored signed integer parsed from the bounded AC clause, caster subject, activation revision, prose turn duration and triggering-attack inclusion |
| `spell-declared-duration-v1` / `structured-duration` | Reference to duration index 0 after verifying a timed one-round declaration, self range, no unsupported end condition or concentration/up-to qualifier |
| `shield-turn-boundary-v1` / `turn-boundary` | Separate caster-relative START_OF_NEXT_TURN interpretation from its exact prose clause |
| `shield-special-interaction-v1` / `magic-missile-protection` | Spell-specific prevention with authored tagged mention, activation and prose-duration context; no general immunity or damage-type rule |

The prose patterns require the complete supported clause through the final spell tag and period.
They reject added conditions, missing inclusion wording, extra body entries, unknown tags, extra tag
arguments and malformed syntax. Numeric tokens are read from source rather than copied from an
expected result. In-memory perturbation tests demonstrate a changed numeric value is actually read;
the production entry point rejects such altered resources because their pinned fingerprints changed.

PHB trigger wording produces `ATTACK_HIT`; XPHB produces `ATTACK_ROLL_HIT`. Both preserve attack
first, spell targeting second. PHB's targeting mention is an unqualified tag. XPHB's targeting mention
is plain text and has no authored source qualifier. The body protection tag is unqualified in PHB
and explicitly `XPHB` in XPHB. Names retain authored case. All mention resolution states remain
`NOT_ATTEMPTED`, without target IDs or resolver occurrences. No source default is inferred.

## Evidence, provenance and assembly

| Owner | Original resource / root | SHA-256 |
| --- | --- | --- |
| `spell:phb:shield` | `data/spells/spells-phb.json#/spell/294` | `c9e54cce55e7ce0fc988feb1b604bf505faa5c042635542fa6b6ed36724e297a` |
| `spell:xphb:shield` | `data/spells/spells-xphb.json#/spell/304` | `442544a91aad1181cbad78d49cfa48f9ced7d8b048dbc781e32fa6fefc6278b9` |

Original names, source/page, structured values, collection sizes and normalized strings are checked
against the authored bytes. Known optional flags and duration end lists are checked without losing
meaningful false values. Private JSON-tree reads locate/hash source evidence; known application
values remain typed existing records. No new source DTE or generic effects structure was added.

Each document has **13 distinct evidence records and 17 claim associations**. Text records retain
the exact decoded-string hash, original hierarchy and UTF-16 `[start,end)` span. Structured records
retain the original JSON Pointer and value hash, with no invented text offset. Original bytes are
never mutated, and complete source prose is not copied into the inspection response.

Evidence IDs bind resource fingerprint, owner/pointer and span where applicable. Local IDs differ
from benchmark IDs; exact source locators, values and claim associations match. Mechanic identities
use `mechanic:spell:<source>:shield:<stable-slot>`, independent of numeric values, array filtering,
review or rights. Claims/documents begin at revision 1 with canonical content hashes binding their
source, context, evidence and derivation. Repeated construction is byte/record deterministic.

All origins are AUTHORED. These two Spell roots do not require inherited/transformed evidence;
PHB reprint relationships are not treated as XPHB inheritance. AC and protection bind the exact
materialized activation revision. If activation cannot be established, those dependent claims abstain
instead of creating dangling references. The canonical join validates final evidence and references.

Pattern misses emit controlled `UnsupportedMechanicsConstruct` values anchored to the nearest
actually present source node. Missing fields never receive fabricated text spans. Independent
duration patterns can survive a trigger miss; recognized metadata can survive a prose miss. If none
of the five patterns is supported, processing is PROCESSED / NONE_SUPPORTED with explicit
abstentions. It is not NOT_ATTEMPTED and does not mean the Spell has no mechanics.

Fingerprint/owner/normalization mismatches, missing resources and invalid canonical relationships
fail startup. The service does not catch these as successful empty documents. No recoverable runtime
failure state is invented; the existing canonical FAILED → UNAVAILABLE projection remains intact.

## Coverage, review, rights and publication

Exactly **2 owners are PROCESSED**, five claims each. The other **967 remain NOT_ATTEMPTED /
NOT_ASSESSED**. All 930 formula observations on 422 owners remain unchanged; 547 owners still
have no indexed formulas. Shield itself has no formula observations, while now having real effects.

Successful Shield documents deliberately report PARTIAL. Their considered paths are time, range,
duration and entries. Entries also remain unassessed as a whole because recognizing the bounded
clause does not establish exhaustive interpretation of every descriptive statement. Coverage paths
can therefore overlap at container granularity. There is no assertion of whole-Spell completeness.

Every bounded claim is COMPLETE_WITHIN_CLAIM. Every recorded review state is PENDING_REVIEW;
there are no human decisions. Existing quality rules derive, per edition:

- **2 PENDING_REVIEW:** declared duration and prose turn boundary.
- **3 NEEDS_MECHANICS_REVIEW:** reaction and prevention contain unresolved Spell mentions; AC
  depends on the review-blocked activation. Protection also retains that dependency finding.
- **0 VERIFIED / 0 REJECTED.** Across both editions: four pending, six needing mechanics review.
- **All 10 licensing classifications are NEEDS_REVIEW / NOT_ASSESSED.** Source SRD flags,
  successful pattern recognition and candidate comparisons confer no rights or publication approval.

P1D remains separate and authorizes zero formula observations. Inspection is not filtered by rights,
review or publication state. The API must remain network-private until an appropriate server-side
external policy exists. No profile, authentication implementation or caller-controlled privilege view
was introduced.

## Limitations and handoff to 7.3.3

1. Only the two pinned Shield roots and the five documented patterns are enabled. Revised source
   bytes require explicit input review and a new pinned revision; modified-source tests run in memory
   and cannot activate their input through production startup.
2. Exact wording is intentionally conservative. Unsupported variants abstain rather than becoming
   guessed mechanics. No general NLP parser, combat engine, final AC calculation, stacking,
   attack negation, general force immunity or automatic target resolution exists.
3. References remain unattempted. Human fixture review must adjudicate proposed expectations
   before gold acceptance; a future source-resolution change needs separate scope and revised
   review evidence. Candidate matches never grant VERIFIED or publication authorization.
4. Scope coverage remains partial. The interpreted clause does not establish all possible Shield
   mechanics. Other 967 Spell documents remain unattempted, including all four future controls.
5. Step 7.3.3 should use the existing benchmark infrastructure for independently reviewed and held-out
   cases, measured error/abstention behavior and claim-local diagnostic criteria. It must not quietly
   broaden the extractor or promote pending fixtures. It requires separate authorization.

No other Spell extractor, model expansion, database, Keycloak, frontend work or repository cleanup
was implemented.
