# 7.2.3 — Additive Spell mechanics inspection API

Status: implemented and verified, 18 October 2026. Step 7.2 exit criteria pass.

References: [7.2.1 contract](7.2.1-mechanics-model-and-api-contract.md),
[7.2.2 canonical model](7.2.2-canonical-mechanics-model-implementation.md).

## 1. Implemented REST contract

```http
GET /api/spells/spell:phb:shield
GET /api/spells/spell:phb:shield?include=interpretedMechanics
GET /api/spells/spell:xphb:shield?include=interpretedMechanics
GET /api/spells/by-name/Shield?source=PHB&include=interpretedMechanics
```

Only detail and by-name accept the new include. The exact supported value is
`interpretedMechanics`; blank, unknown, differently cased and combined unsupported values return
the existing `IllegalArgumentException` / HTTP 400 response style. Without include, the new field
is null and omitted. By-name remains a list, including both PHB and XPHB Shield if source is absent.
Unknown IDs/names retain their existing 404 behavior. Existing filters and list/summaries are
unchanged; collection routes do not acquire an include projection or new query validation.

`SpellDto` appends nullable `SpellMechanicsInspectionDto interpretedMechanics`. Both the existing
14-argument pre-P1A and 15-argument P1A constructors remain as delegating overloads with null
inspection. Existing service overloads and standalone mapper construction remain usable. A legacy
standalone service without an inspection catalog cannot claim successful opt-in inspection; it
fails explicitly. The actual Spring service always receives the startup-validated catalog.

Adding a record component changes record reflection, the canonical constructor, component count,
equality shape and record patterns. The overloads preserve ordinary Java constructor source usage;
they do not promise compatibility for every reflection/pattern-based client.

## 3. Runtime flow and integrity

```text
Existing SpellCatalog + Batch 6 formula index
                +
Typed authored owner/source manifest (startup only)
                ↓
Unattempted canonical MechanicsDocument per authoritative Spell ID
                ↓
Owner/source/fingerprint/observation validation
                ↓
Immutable ID-indexed inspection DTOs
                ↓
Opt-in existing detail/by-name mapping
```

Batch 6 already validates its authored owner set, but its formula index does not retain a source
locator for owners with zero tags. The new factory reads the 18 Spell resources once at startup
using the existing strict `SpellFileDte`/`SpellDte` schema, fingerprints actual resource bytes,
and records actual root pointers. It never derives a resource path from an assumed source code.
It uses the existing `SpellIdentityFactory`, Source Registry, normalized sources and catalog/index
joins. There is no new markup parser or formula classifier.

Startup validates:

- Exact equality of normalized owners, authored manifest owners, formula-index owners and document
  owners; duplicate, missing and unknown owners fail.
- Source/page identity and verified artifact revision correspondence, including owners with no
  formulas. Conflicting or changed resource fingerprints fail.
- Every canonical formula reference joins the existing owner/ordinal/evidence in Batch 6.
  Formula-root pointers, resource paths, fingerprints and occurrence order must agree.
- Every expected formula occurrence appears once in its owner's canonical document. Missing,
  reordered or duplicate references cannot masquerade as a complete join.
- Canonical document integrity, Source Registry references, any declared duration references,
  evidence relationships and review summaries through the existing 7.2.2 validators.

Failures stop catalog construction/startup. They are not caught and converted to an empty success.
The explicit canonical-document constructor is the future 7.3 adapter boundary: a separately
authorized implementation can supply real documents with the verified manifest, while retaining
this catalog validation, mapper and REST contract. The manifest is trusted backend input produced
from pinned classpath resources, never request data.

Requests perform immutable ID lookups. They do not reparse source JSON, scan a corpus, resolve
references, evaluate formulas or consult publication candidates.

Empty lists are omitted under `@JsonInclude(NON_EMPTY)`. Zero review/coverage counts remain visible.
No aggregate review or licensing status is invented for a nonexistent mechanic. For future actual
claims, individual assessment completeness, recorded/effective review and rights remain separate.

The 547 owners without observations do **not** have an assertion of no mechanics. Shield's existing
`formulaProjectionStatus=NONE_OBSERVED` still concerns bounded formula indexing only; its inspection
is unattempted. Fireball's `WITHHELD` remains unchanged even though the private envelope contains
observation references. References are not formulas or applied effects.

Synthetic projection tests distinguish:

- Available/unattempted, assessed `NONE_SUPPORTED`, and available partial interpretations.
- Failed canonical processing: `availability=UNAVAILABLE`, `processing.state=FAILED`,
  `coverage.status=NOT_ASSESSED`, and controlled diagnostic `INTERPRETATION_PROCESSING_FAILED`.
- No fabricated arbitrary exception-to-unavailability behavior. Production currently has no
  interpreter failure state; integrity errors remain startup failures.

## 5. Evidence and observation handling

Exactly **930 authored formula references across 422 owners** are projected, preserving Batch 6
ordinals and deterministic order. IDs are `spell:<source>:<slug>:formula:<existing-occurrence-index>`.
The source revision binds those ordinals to the pinned corpus; they are not new mechanic identities.
The remaining **547 owners** have an omitted empty observations list.

Each formula reference has a Spell ID, occurrence index, source revision ID and inline bounded
evidence locator. It publishes no token expression, arguments, formula role or gameplay relationship.
All 930 original UTF-16 spans are reconstructed in the corpus test against original source strings
and compared to Batch 6 tokens. No modified or inferred spans are created.

Claim evidence and observation evidence have different roles. Initial documents have no interpreted
claims and an empty claim-evidence pool. The existing formula references nevertheless have real
inline locators. This does not fabricate evidence for an unattempted Shield interpretation.

Text locators retain JSON owner/text pointers and exact UTF-16 `[start,end)` spans. Structured-field
locators have no fake text spans. Transformed locators expose effective locations and input evidence
IDs, without pretending generated output has an original source span. Unavailable-origin locators
explicitly have no original span. Generic syntax references with unavailable origin retain that
limitation; source qualification is omitted if the canonical reference does not establish it.

Source revision IDs are document-local resource paths, with dataset version and SHA-256 in the
revision table. The owning Spell's existing `source` establishes source identity; evidence records
retain an original `SourceReference` when established. The table does not assume a file always has
one publication code. Clients must compare revision fingerprints, not resource IDs alone.

## 7. Privacy, publication and deployment

**This include must remain network-private until an appropriate backend external-access and
publication policy is implemented.** Existing `/api/**` security behavior is unchanged; the include
is a data request, not authentication. No additional development profile, caller-selected privilege
view, Keycloak, frontend filtering or role implementation was introduced. CORS is not access control.

Inspection is not filtered by P1D authorization, rights status or mechanics review. Future pending,
review-required, rejected and rights-unreviewed claims remain inspectable. The projection returns
individual computed states; synthetic tests exercise all four review and all four licensing states.
VERIFIED fixtures use validated synthetic human decisions bound to exact claim revisions. Established
rights fixtures use synthetic scoped evidence. None are production approvals or reviewed benchmarks.

The mapper omits human reviewer IDs, authority mandates, decision rationale/timestamps, supersession
journals, prior rights determinations and internal publication resources. It projects bounded
locators rather than complete source text. Canonical payload/context types are reused; precise
nested claim-revision references retain their canonical bindings. Root audit digests/decisions are
not copied wholesale into the DTO.

## 9. Design refinements and handoff

The 7.2.1 contract remains intact. Concrete refinements from illustrative signatures:

- Source-revision IDs use actual resource paths rather than invented labels such as `phb-v2370`.
  Source identity remains on the authoritative outer Spell and on established evidence sources.
- The existing canonical processing/coverage/review types are reused. `diagnostics` is an optional
  additional envelope field only for an actual canonical `FAILED` state.
- Formula observations use a dedicated reference DTO, not the full syntax observation containing
  tokens/prose. Source hierarchy is bounded to owner/text pointers and exact span in the response;
  the complete original hierarchy remains internal.
- The narrowly demonstrated transformed-evidence defensive-copy defect was fixed, with regression
  coverage. No normalization or interpretation semantics changed.

Before a separately authorized Step 7.3 interpretation pilot:

1. Establish independently reviewed expected cases, including PHB and XPHB Shield separately;
   current construction tests are not that benchmark.
2. Supply source-supported canonical documents through the existing adapter boundary. Validate
   actual source claims, context associations, evidence hashes and revisions; do not copy the
   illustrative 7.2.1 effects into production.
3. Keep unsupported/unknown/partial results explicit. Review and rights remain independent;
   neither benchmark success nor an SRD flag grants VERIFIED or publication permission.
4. Preserve existing formulas, structured Spell mechanics, default APIs and source distinctions.
   The opt-in projection need not be replaced when interpreted documents become available.
5. Do not expose the inspection externally without a server-side policy and authorization boundary.

Step 7.2 is complete. No interpreter, Shield/Fireball extraction, benchmark suite, database,
authentication implementation, frontend or repository cleanup was started.
