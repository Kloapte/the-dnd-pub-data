## Existing model fit and preimplementation decision

`SpellTargetSubject` currently combines a `TargetScope`, optional creature-type restriction and
optional maximum target count. `TargetScope` has creature-only single, multiple, area and
caster/touched forms. It has no scope for one selected creature-or-object target. `AttackRollMechanic`
represents one independent cast-time spell attack, `DamageMechanic` represents typed damage, and
`AppliesOnAttackRollOutcome` binds damage to an exact attack claim revision. Step 7.4.4I's typed
`CharacterLevelDamageScaling` is appropriate for Fire Bolt's explicitly authored character-level
progression and remains separate from slot-level scaling.

The selected minimal target extension is a generic `SINGLE_TARGET` scope plus an immutable,
deterministically ordered `eligibleTargetCategories` list on `SpellTargetSubject`. The scope fixes
cardinality at exactly one; the categories describe mutually exclusive eligibility alternatives for
that one target. This retains existing creature-only scopes and omits the new optional list for all
existing claims. The bounded PHB pilot will require exactly `[CREATURE, OBJECT]`; target allocation,
multiple selected targets and areas remain out of scope.

There is no canonical object-property or ignition-effect model. A typed ignition claim cannot safely
represent flammability, the qualifying hit, and not-worn-or-carried applicability. The extraction
will therefore retain a source-backed unsupported diagnostic for ignition while separately
supporting object eligibility for the attack and its hit-bound damage.

## Implementation and verification results

### Target model

Added `TargetCategory` with `CREATURE` and `OBJECT`, plus `TargetScope.SINGLE_TARGET` and an
optional immutable `SpellTargetSubject.eligibleTargetCategories`. This represents one target
selected from alternatives. The constructor requires the canonical ordered pair
`[CREATURE, OBJECT]` for this scope, disallows empty/duplicate/unknown category values and rejects
target categories on creature-only or multi-target scopes. Existing `SINGLE_TARGET_CREATURE`
subjects retain their prior serialized form and behavior.
