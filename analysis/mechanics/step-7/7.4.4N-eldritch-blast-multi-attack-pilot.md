## Canonical model and extraction

Added the immutable model values `InstanceCountProgression`,
`CharacterLevelInstanceCount`, and `CharacterLevelInstanceCountTier`. The only implemented
progression variant is character-level based; spell-slot instance-count scaling remains deferred.
Tier levels must be within 2–20 and strictly increase. Total counts must be positive and increase
with each tier. `AttackRollMechanic` also requires a progressive count to exceed its base count and
requires `attacksIndependent=true`. Existing five-argument construction remains available, and
optional progression/allocation fields serialize as omitted when null, preserving all existing
single-attack payload bytes.

Added `InstanceTargetAllocation` using typed `TargetSelectionCardinality` and `TargetReusePolicy`
values. It records exactly one creature target per beam, selection within the Spell's range, and
`REUSE_ALLOWED`. This allows each beam to choose the same creature or another creature. No target
IDs or shared target set are stored. The existing `SpellTargetSubject(SINGLE_TARGET_CREATURE)` is
the target of each individual attack/damage event; the allocation field makes explicit that separate
beams can select different such targets.

Added `AppliesOnEachAttackRollOutcome` with `HIT` and
`CORRESPONDING_ATTACK_INSTANCE`. The damage claim points one way to the attack claim's exact
revision-bound ID, revision number and content hash. It means a beam's own hit causes one 1d10 force
damage instance to that beam's selected creature. It does not create attack claim IDs for runtime
beams, make one shared HIT apply across beams, or aggregate successful beams into one damage event.
Document validation checks the referenced claim exists, is an attack-roll mechanic, is independent,
has the current revision/hash, is owned by the same Spell, and has the same target subject. Target
allocation categories must also agree with the typed Spell target subject. No reverse claim
dependency was added.

The existing `DamageMechanic` remains the amount carrier. Its character-level scaling is null, and
the document contains no spell-slot scaling claim. The shared PHB attack extraction and assembly path
was extended with one bounded source-aware Eldritch Blast rule; production eligibility remains an
explicit single-owner addition. It emits exactly two claims and no unsupported diagnostics. The
document remains `PARTIAL` because the existing assembly leaves `/spell/113/entries` unassessed; this
owner is not represented as fully covered merely because its extracted claims are complete within
claim scope.
