# Step 7.5 — Generic Scaling Extraction and Relationship Strategy

## Summary

Added an experimental, source-aware scaling mechanic for spell-slot and character-level progressions, plus a relationship that binds each scaling rule to one specifically affected mechanic. Scaling remains separate from its base attack, damage, or healing payload. The implementation does not evaluate progressions or change canonical extraction.

The final catalogue run evaluated 969 owners from 18 pinned resources and emitted 229 scaling mechanics with 150 scaling relationships. Unresolved and ambiguous scaling remains visible in experimental diagnostics. Canonical claims and decisions remained unchanged.

## Design and implementation

`GenericScalingMechanic` is an independent typed payload. It records the axis, progression form, quantity, optional base level, and immutable progression steps. Supported axes are `SPELL_SLOT_LEVEL` and `CHARACTER_LEVEL`; supported progression forms distinguish per-level increments, fixed-threshold increments, and threshold values. Step amounts reuse the existing typed `AmountExpression` model, including dice and fixed integer values. Validation checks axis-specific bounds, ordered thresholds, nonempty steps, and valid amount expressions. The model describes progression; it does not calculate a character's resulting value.

The generic source normalizer preserves entry hierarchy and source pointers, including `entriesHigherLevel` and structured `scalingLevelDice`. The scaling extractor recognizes explicit slot increments, authored threshold increases, cantrip-style character-level tables, and supported count changes. It does not infer a progression from a spell name, a bare “At Higher Levels” heading, general game rules, or a mere co-occurrence with damage. Unsupported or incomplete scaling candidates remain diagnostics.

`ScalingRelationshipStrategy` runs through the existing relationship registry after extraction. It connects a scaling mechanic to a single compatible damage, healing, or attack mechanic only when the source text and extracted quantity/type identify an unambiguous target. It can resolve across source fragments. Multiple possible targets, unknown quantities, and unsupported source references abstain with diagnostics. Relationships use stable IDs, the owner and pinned source revision, and source evidence. The experimental DTO validator verifies endpoint ownership/revision/evidence and rejects invalid or cyclic static references.

The parser also now preserves explicit signed-dice modifiers in supported expressions, and healing expressions such as `1d4 + your spellcasting ability modifier` retain the symbolic caster modifier. This allows scaling relationships to point at the actual amount-bearing mechanic without fixing the modifier to a number.

## Representative source-backed cases

- `spell:phb:fireball`: slot-level progression starts from base slot 3 and adds 1d6 damage at each higher slot; linked to its damage mechanic.
- `spell:phb:healing-word`: adds 1d4 healing for each slot above first; linked to the healing expression, which retains the caster's symbolic spellcasting modifier.
- `spell:phb:scorching-ray`: each slot above second adds one projectile; linked as `PROJECTILE_COUNT`, distinct from damage-amount scaling.
- `spell:phb:eldritch-blast`: character-level thresholds 5, 11, and 17 set the number of attacks to 2, 3, and 4; linked to its attack mechanic.
- `spell:phb:ray-of-frost`: character-level thresholds preserve the authored 1d8/2d8/3d8/4d8 damage values; linked to cold damage.
- `spell:phb:magic-missile`: slots above first add one projectile; the relationship identifies projectile count, not damage dice progression.
- `spell:xge:ice-knife`: slot levels above first add 1d6 to the cold damage mechanic, independently of the initial piercing damage.

## Comparison with v3 and compatibility

The v3 baseline had 1,199 candidate mechanics, 546 owners with candidates, 747 `CANDIDATE_PARTIAL` outcomes, 222 `NO_PATTERN_MATCH` outcomes, 216 saving-throw-to-damage relationships, and 45 attack-to-damage relationships. V4 has 1,437 mechanics, 570 candidate owners, 757 partial outcomes, and 212 no-match outcomes. It retains all 45 attack relationships and all 216 prior save relationships, and adds five source-supported save/damage relationships for `spell:au:negative-energy-flood`, `spell:phb:disintegrate`, `spell:phb:finger-of-death`, `spell:xphb:disintegrate`, and `spell:xphb:finger-of-death`. No save or attack relationship was removed.

Payload-only comparison reports 1,194 exact payload matches, 5 v3 payloads not reproduced, and 243 v4 additions. The five unmatched payloads are prior healing expressions that omitted the authored symbolic spellcasting ability modifier; v4 emits their corrected sum expressions. The 243 additions include the 229 new scaling mechanics and additional/updated payloads enabled by preserving explicit numeric modifiers. A payload-only comparison does not prove semantic equivalence; these differences are retained for review rather than applied to canonical claims.

The API dry run reports 129 canonical owners and 279 claims, and confirms the canonical claim snapshot is exactly stable. The API still exposes scaling only within the optional experimental mechanics include. Review, licensing and publication state remain independent and unchanged.

## Limitations

The extracted rules are experimental candidates, not verified interpretations. The current strategy supports a bounded set of explicit amount and count progressions; unsupported formulas, implicit baselines, non-numeric quantities, or ambiguous cross-fragment references remain unresolved. Relationship matching is intentionally conservative and may leave legitimate rules unbound where the source's affected quantity cannot be isolated. The model does not evaluate scaling, execute attacks, choose targets, or resolve character statistics. Canonical extraction, review, licensing, publication authorization, and roadmap statuses were not changed.
